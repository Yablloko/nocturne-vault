# Аудит безопасности Android-сборки Nocturne

Дата: 3 сентября 2026 года

Проверенная версия после исправлений: 0.9.11, code 29

Объект проверки: локальная рабочая копия Android-проекта Nocturne 0.9.11 после исправлений защищённого пространства.

Сохранённое покрытие: 464 поверхности, 86 отложенных кандидатов, 87 открытых вопросов, 12 отклонённых кандидатов. Поэтому этот документ не является заявлением об отсутствии других уязвимостей.

## Исправленные проблемы

|---|---|
| Личная сессия после выключения экрана | Расшифрованный ключ немедленно удаляется. При следующем открытии требуется фактор Nocturne. |
| Внешний выбор файлов и системные окна | Таймер больше не останавливается. Просроченная сессия блокируется до обработки результата. |

| Буфер обмена | Секрет Nocturne очищается сразу при уходе приложения в фон, а не после возвращения. |
| Задержка после неверных паролей | Используются монотонные часы. Перевод времени не снимает блокировку; после перезагрузки задержка начинается заново. |
| Сессия защищённых приложений | Срок хранится по монотонным часам. Откат системного времени не продлевает сессию. |
| Аварийное закрытие профиля | Требуется точный системный таймер. Если Android его не разрешил, пространство не открывается и показывает понятную кнопку выдачи разрешения. |
| Межпрофильная команда | Маршрут проверяется до запуска: принимается только системный пересыльщик Android. Основной переход использует `ACTION_MAIN` с закрытой категорией без `LAUNCHER`, запускается отдельной задачей и сохраняет прежний маршрут только как совместимый fallback. Рабочая копия возвращает одноразовое подтверждение фактического получения и результата команды. |
| Неавторизованный запуск контроллера | Политики и приостановка приложений применяются только после проверки подписанной команды либо в доверенных системных событиях. |
| Приостановка приложений | Проверяются все пользовательские пакеты, включая приложения без иконки запуска. Для пользовательски запускаемого пакета закрытое состояние принимается только после скрытия либо подтверждённой системной приостановки; это учитывает OEM-пакеты, которые запрещено скрывать. |
| ZIP-документы | Общий лимит распаковки учитывает и нужные, и пропущенные записи. ZIP-бомба останавливается до исчерпания памяти. |
| Изображения | Размер декодированного изображения ограничен одновременно по сторонам и числу пикселей; результат дополнительно проверяется после декодирования. |
| Метаданные импортируемого файла | Медленный или вредоносный ContentProvider больше не блокирует главный UI-поток. |
| Сборочный кэш | Сборка всегда очищает промежуточный DEX. Это исключает APK со смесью старых и новых сигнатур методов. |
| Переподключение рабочего профиля | Ручные и одноразовые коды удалены. Открытая личная копия отправляет самоподписанный запрос замены ключа, действующий 5 минут; рабочая копия принимает его только вместе с системным `PendingIntent`, созданным тем же пакетом в другом связанном профиле. Nonce не принимается повторно. Если профиль заперт, его отдельный PIN/рисунок/пароль запрашивает сам Android до запуска контроллера. |
| Резервные копии | Идентичность управления рабочим профилем переносится только внутри зашифрованного master-паролем payload. При импорте после сброса она восстанавливает прежнюю связь; при импорте в уже открытое локальное хранилище приоритет имеет текущая связка этого устройства. Пара ключей криптографически проверяется до установки копии. |
| Перезагрузка устройства | Заблокированная загрузка и обновление пакета безусловно закрывают рабочую сессию и очищают её дедлайн. Обычное `USER_UNLOCKED` лишь повторно применяет изоляцию и не уничтожает только что разблокированную пользователем сессию. Старое значение `elapsedRealtime` не переживает перезагрузку как активная сессия. |
| Возврат из гостевого приложения | Активность сначала проверяет срок сессии и только затем применяет политику. Просроченная сессия не может кратко снять приостановку с последнего приложения. |
| Истечение сессии во время запуска | Перед запуском требуется запас не менее пяти секунд, а срок повторно проверяется после подготовки пакетов. При истечении сессии все гостевые приложения блокируются вместо запуска. |
| Просроченное окно защищённого пространства | Окно само закрывается по локальному таймеру. Запуск приложения и открытие магазина дополнительно проверяют действующую сессию непосредственно перед действием. |
| Реклама и сеть | Неиспользуемый Yandex Mobile Ads SDK удалён вместе с кодом баннеров. Из итогового APK удалены `INTERNET`, `ACCESS_NETWORK_STATE`, `AD_ID` и код Yandex. |
| Цепочка сборки | Зафиксированы версии и SHA-256 зависимостей, SHA-256 дистрибутива и Wrapper JAR Gradle. Подписание больше не создаёт новый ключ автоматически и проверяет постоянный сертификат и схемы v2/v3. |
| Создание защищённого пространства | Системный мастер больше не считается бездействием. Автоблокировка приостанавливается только на время создания, не более чем на 30 минут; выключение экрана по-прежнему немедленно закрывает хранилище. |
| Сообщения рабочего профиля | Внутренние англоязычные коды скрыты. Пользователь видит понятное описание причины и дальнейшего действия. |
| Выключенный рабочий профиль | Состояние системной кнопки с портфелем определяется отдельно. Вместо неработающих команд показывается кнопка включения рабочего пространства. |
| Навигация | Защищённые приложения вынесены из настроек в самостоятельный раздел нижнего меню с описанием, состоянием и последовательностью настройки. |
| Необходимые разрешения | В рабочем пространстве показаны только действия, которые должен выполнить пользователь: точное закрытие и отдельный код. Каждый пункт объяснён и открывает нужный экран Android. |
| Состояние рабочего профиля | Удалён недоступный обычному приложению вызов quiet mode. Состояние обновляется по официальным системным событиям Android, а инструкция включения показывается внутри Nocturne. |
| Проверка отдельного кода | Объявлена политика `limit-password`; наличие отдельного кода больше не зависит от вызова, который выбрасывал `SecurityException`. Состояние обновляется после возврата из системного экрана. |
| Видимость гостевых приложений | В закрытом состоянии гостевые пакеты не только приостанавливаются, но и скрываются через политику владельца профиля. Перед разрешённым запуском скрытие снимается только с выбранного пакета. |
| Переподключение | Дополнительный экран аутентификации и одноразовый код Nocturne удалены. После системной разблокировки профиля доверенная короткоживущая команда автоматически меняет ключ и открывает сессию; прямой запуск рабочей Activity без команды закрывает сессию. |
| OEM-проверка отдельного кода | Удалены локальные флаги и ошибочное требование одновременного успеха четырёх OEM-зависимых API. Объединённый или отсутствующий код не может быть принят локальным fallback. |
| Системная аутентификация профиля | Nocturne не показывает собственное окно ввода рабочего кода и не получает его. Если credential-encryption key вытеснен, межпрофильный системный переход Android сам показывает экран отдельного рабочего PIN/рисунка/пароля; после успешной проверки контроллер продолжает исходную подписанную команду. |
| Возврат из настройки рабочего кода | Перед открытием системного экрана повторно применяется запрет объединённого пароля. После возврата Nocturne до 4,5 минуты опрашивает официальный признак отдельного challenge и автоматически продолжает переподключение, даже если OEM рано вернул управление приложению. Если Android сообщил «Сохранено», но сохранил общий код телефона, состояние остаётся `SETUP_REQUIRED`: приложение не выдаёт ложное «Готово», остаётся закрытым и показывает понятную инструкцию выбрать другой код. |
| Справка защищённых приложений | Множество раскрывающихся блоков убрано с основного экрана. Полное описание архитектуры, ограничений, отдельного кода и переподключения вынесено на самостоятельный экран «Справка». |

## Проверенные, но не изменённые решения

Сброс локального хранилища без секрета Nocturne оставлен. Он затрагивает доступность, но не раскрывает данные. В рассматриваемой модели атакующий уже знает пароль Android и может получить тот же результат через удаление приложения или очистку его данных. Текст `СБРОСИТЬ` защищает от случайного действия; дополнительный пароль внутри приложения не создаст реальной границы против такого атакующего.

Обычное автозаполнение сайтов оставляет явное предупреждение и требует отдельного подтверждения перед передачей данных приложению, заявившему домен. Криптографически связать произвольный сайт с браузером средствами старого Autofill API нельзя без потери автозаполнения сайтов. Это остаётся риском социальной инженерии, а не автоматической выдачей пароля.

## Оставшиеся риски и непроверенные области

1. Обработчик выключения экрана рабочего профиля живёт в процессе контроллера. Если Android завершит этот процесс во время работающего гостевого приложения, немедленная реакция на выключение экрана не гарантируется. Точный аварийный таймер ограничивает сессию пятью минутами, а отдельный код рабочего профиля остаётся обязательным, но это не равно мгновенной блокировке на каждом OEM.
2. Проверка выполнена на AOSP-эмуляторе API 36. Нужна матрица реальных Samsung, Pixel, Xiaomi и других поддерживаемых устройств: убийство процесса DPC, энергосбережение, перезагрузка, выключение экрана, истечение таймера и ввод отдельного кода профиля.
3. Контролируемый мост из зашифрованной медиатеки Nocturne в рабочий профиль ещё не реализован. Общий Android-доступ между профилями намеренно запрещён, потому что обычное копирование оставило бы расшифрованные файлы в рабочем профиле.
4. Managed profile — изоляция Android, а не виртуальная машина. Уязвимость ядра, root, скомпрометированная прошивка или производитель устройства остаются за пределами гарантий приложения.

## Выполненные проверки

- Чистая сборка `build-android.ps1`: успешно.
- Модульные тесты `testDebugUnitTest`: 37 тестов в 6 наборах, 0 падений и 0 пропусков, включая негативные проверки ZIP, изображений и монотонной блокировки.
- Android Lint `lintDebug`: успешно, ошибок нет.
- Полный instrumentation-прогон в личном профиле API 36: 38 тестов, 0 падений, 4 профильных сценария ожидаемо пропущены; DPC-сценарии отдельно выполнены внутри рабочего профиля.
- Managed profile API 36: 6 тестов, 0 падений — 3 применимых DPC-сценария выполнены, 3 сценария ожидаемо пропущены из-за стороны профиля либо отсутствия тестового гостевого пакета; проверены политика, подписанная команда, защита от повтора и подмены и изоляция системных приложений.
- Фактический запуск команды из личного профиля через проверенный системный межпрофильный компонент — успешно; после системного рабочего PIN целевая копия вернула подтверждение `REPAIRED`, новый ключ сохранён и сессия открыта. В рабочем профиле нет `MAIN/LAUNCHER`-активности Nocturne.
- Чистый сценарий создания отдельного кода проверен на новом рабочем профиле: сначала возвращён `SETUP_REQUIRED`, спустя более 30 секунд после настройки Android автоматически продолжена та же доверенная команда; после выдачи точного таймера получены `REPAIRED` и затем `LOCKED`.
- Отсутствие разрешения точного таймера проверено отдельно: запуск отклонён с `EXACT_LOCK_UNAVAILABLE`, сессия не создана. После выдачи разрешения положительный сценарий успешно пройден.
- Автоматическое переподключение выполнено внутри рабочего профиля: новый ключ принят, повтор той же команды с тем же nonce отклонён.
- Итоговый release APK 0.9.11 (29) подписан постоянным RSA-4096 сертификатом; схемы v2/v3, package, версия, min/target SDK и разрешения проверены автоматически. ## Вывод

Подтверждённые исходным сканом проблемы, для которых существовало безопасное локальное исправление, устранены и проверены. Подписанный release APK и его зависимости проверены. Нельзя утверждать, что приложение защищает от всех атак: глубокий скан завершился аварийно, проверка OEM остаётся обязательной, а процесс-независимая мгновенная блокировка рабочего профиля требует системной поддержки или испытанного OEM-решения.
